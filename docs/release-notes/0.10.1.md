## What's new in 0.10.1

### Fixes

- **No change for Subtext's forbidden paths, which answer 301 on 0.10.0** (the smoke test). Request filtering still
  answers 404.8 for a hidden segment (`/App_Data/`, `/bin_dotnet/...`) before any module runs, as on IIS. Subtext's
  Web.config sends every 404 to an error page by `<httpErrors errorMode="Custom">` `ExecuteURL`, and the page's URL
  (`/Subtext.Web/pages/...`, the folder Subtext was developed in) makes Subtext's `BlogRequestModule` redirect the child
  request permanently. Since 0.10.0 the response is the child request's, with its status, as on IIS 10 (#192); 0.9.0
  put the 404 back on it and sent Subtext's 301 as a 404 with a `Location`. IIS.Gate.Tests' `ErrorsAndLimitsTests` pin
  this, and CI's `iis-compare` job checks the same requests against IIS 10. An application that wants a 404 from its
  `ExecuteURL` page sets `Response.StatusCode = 404` there, or points `<httpErrors>` at a URL the application serves.
- **A POST or PUT that arrives as an application restarts is answered by the next worker** (#214). A request with a
  body that reached the old worker just as its application began shutting down got 503 ("Server Too Busy", or the
  worker's own 503 with an `X-WebForCore-Restarting` header), because webforcore-host had already sent its body to the
  old worker and couldn't send the request again; on IIS http.sys queues it and the next worker process serves it.
  The host now keeps a body of up to 49,152 bytes (IIS's `uploadReadAheadSize`) until the request is answered, and
  sends a larger body, or one of unknown length, to the worker only once the application reads it
  (`Expect: 100-continue` between the host and the worker; the application doesn't see the header). A worker that
  turns a request away hasn't read its body, so the host sends the request, body and all, to the next worker. In
  IIS.Gate.Tests' new `RecyclingTests.RequestsWithBodiesDuringRepeatedRestartsUnderLoadAreAllAnswered` (16 clients
  posting forms and putting raw bodies of 200 bytes to 100 KB, some chunked, across 5 restarts) 18 to 37 requests
  in each run of about 2,000 got 503 before.
