## What's new in 0.10.1

### Fixes

- **No change for Subtext's forbidden paths, which answer 301 on 0.10.0** (the smoke test). Request filtering still
  answers 404.8 for a hidden segment (`/App_Data/`, `/bin_dotnet/...`) before any module runs, as on IIS. Subtext's
  Web.config sends every 404 to an error page by `<httpErrors errorMode="Custom">` `ExecuteURL`, and the page's URL
  (`/Subtext.Web/pages/...`, the folder Subtext was developed in) makes Subtext's `BlogRequestModule` redirect the child
  request permanently. Since 0.10.0 the response is the child request's, with its status, as on IIS 10 (#192); 0.9.0
  put the 404 back on it and sent Subtext's 301 as a 404 with a `Location`. IIS.Gate.Tests' `ErrorsAndLimitsTests` pin
  this, and CI's `iis-compare` job checks the same requests against IIS 10. An application that wants a 404 from its
  `ExecuteURL` page sets `Response.StatusCode = 404` there, or points `<httpErrors>` at a URL the application serves.
- **`Request.LogonUserIdentity` and `<identity impersonate="true"/>` no longer throw on Linux** (#165). The worker
  request asked `WindowsIdentity.GetCurrent()` for the process's token, which throws `PlatformNotSupportedException`
  off Windows, so reading `Request.LogonUserIdentity`, or any request under `impersonate="true"`, failed with a 500.
  Off Windows the worker request now has no user token, as .NET Framework's `SimpleWorkerRequest`:
  `Request.LogonUserIdentity` is `null` (what .NET Framework returns for a worker request without a token; IIS's is
  the anonymous account's `WindowsIdentity`, which can't exist on Linux), and `impersonate="true"` impersonates
  nothing. `LOGON_USER` and `AUTH_TYPE` are empty, as IIS gives them for an anonymous request, as they already were.
  Windows is unchanged ([NAMESPACES.md](../NAMESPACES.md#systemweb-srcwebformsforcoreweb)). IIS.Gate.Tests'
  `AnonymousIdentityTests` check both platforms, and CI's `iis-compare` job sends the same requests to IIS 10.
