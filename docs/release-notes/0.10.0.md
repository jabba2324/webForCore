## What's new in 0.10.0

### Fixes

- **A request whose path has a `(` keeps its headers** (#170). A path with a `(` that isn't a cookieless-session path
  (`/(S(...))/...`) reached the application without any header IIS has no index for: `Prefer`, `X-Requested-With`,
  `OData-*`, `X-HTTP-Method-Override` and any `X-...` were missing from `Request.Headers`, `ALL_RAW` and Web API's
  `HttpRequestMessage.Headers`. OData keys are in parentheses (`/People(FirstName='Kate',LastName='Jones')`), so a
  `PATCH` with `Prefer: return=representation` answered 204 instead of 200 with the entity (the smoke test's
  `odata-samples-compositekey`). IIS keeps them whatever the path, and CI's `iis-compare` job now checks this against
  IIS 10.
- **A reference to an assembly without a strong name binds whatever the version** (#171), as on .NET Framework, where
  fusion checks versions only for strong-named assemblies. A library built against `Nancy, Version=0.21.1.0,
  PublicKeyToken=null` failed with `FileNotFoundException` when the application deploys Nancy 0.20.0 (JabbR). A
  strong-named reference to a lower deployed version still needs its binding redirect, which isn't applied yet (#158).
- **`Response.Write` with `BufferOutput = false` works** (#184). It threw "The buffer is not associated with this pool"
  in `HttpResponseBufferElement.Recycle`, and the response never ended: Bonobo Git Server's smart HTTP (every clone,
  fetch and push) hung. webForCore's response buffers come from `ArrayPool<byte>.Shared` (.NET Framework's were
  unmanaged), and every buffer went back to the pool, also the arrays the writer only wraps. Now only rented buffers go
  back, as the unmanaged ones were freed, and not while the output cache keeps them; a cached response could be
  sent with another response's bytes. An application's own output cache provider got the whole pool buffer and served
  the page followed by whatever was left in it; it gets the page's bytes, as on .NET Framework.
- **A response that fails while it is being sent ends or is aborted** (#184). When the last chunk of a response
  ASP.NET chunked itself (unbuffered output) couldn't be sent, and the error couldn't be written into it either, the
  client waited for ever; the worker aborts the connection now, so the client sees the response fail.

### Migration guide

More of what the smoke test's migrations found, in [MIGRATING.md](../MIGRATING.md), [NAMESPACES.md](../NAMESPACES.md)
and [AGENT-MIGRATION.md](../AGENT-MIGRATION.md) (its search list and symptom table):

- **Code:** libraries resolve relative paths against `bin_dotnet/`, so a log written there restarts the application at
  every line (mojoPortal's log4net, #173); `AppDomain.RelativeSearchPath` is null (use `HttpRuntime.BinDirectory`,
  #177); `SecurityProtocolType.Ssl3` throws on .NET (#176); LINQ to SQL's generated SQL, `GetCommand().CommandText` as
  well as `DataContext.Log`, has `\n` on Linux (#175).
- **Views:** a Razor 1 view with `@` before a C# keyword in a code block doesn't parse on Razor 3: wrap it in `@( ... )`
  (#174).
- **Libraries:** any prebuilt .NET Framework library that uses `CallContext` fails with `TypeLoadException`, not only
  Log4Net.Async: SimpleInjector 3.1's ExecutionContextScoping (use 3.3.2, #178).
- **Session state stays in process unless it was out of process on IIS** (#180). The guide's `Program.cs`
  ([MIGRATING.md](../MIGRATING.md#4-programcs), AGENT-MIGRATION.md Phase 2 step 6, the README) added
  `AddDistributedMemoryCache()` and `UseAspNetCoreSessionProvider()` to every application that used `Session`. That
  made session state out of process, as StateServer and SQLServer were on IIS, so every value had to be serializable:
  MVCForum, which keeps a view model that isn't `[Serializable]` in MVC's `TempData`, failed the request after creating
  a topic or deleting a member ("Unable to serialize the session state"). Without the provider, session state is in
  process, in .NET Framework's own `InProcSessionStateStore`, as `<sessionState mode="InProc">` (the default) was on
  IIS: values are the objects themselves. The guide now adds the provider only where `<sessionState mode>` was
  `StateServer`, `SQLServer` or `Custom`, or to scale out, says that its values must be serializable, and has the
  error in its symptom tables. The MVC sample and the TestApp run in process; the Web Pages sample uses the provider in
  place of `StateServer`, and the gate checks both.
