## What's new in 0.10.0

### Migration guide

- **Session state stays in process unless it was out of process on IIS** (#180). The guide's `Program.cs`
  ([MIGRATING.md](../MIGRATING.md#4-programcs), AGENT-MIGRATION.md Phase 2 step 6, the README) added
  `AddDistributedMemoryCache()` and `UseAspNetCoreSessionProvider()` to every application that used `Session`. That
  made session state out of process, as StateServer and SQLServer were on IIS, so every value had to be serializable:
  MVCForum, which keeps a view model that isn't `[Serializable]` in MVC's `TempData`, failed the request after creating
  a topic or deleting a member ("Unable to serialize the session state"). Without the provider, session state is in
  process, in .NET Framework's own `InProcSessionStateStore`, as `<sessionState mode="InProc">` (the default) was on
  IIS: values are the objects themselves. The guide now adds the provider only where `<sessionState mode>` was
  `StateServer`, `SQLServer` or `Custom`, or to scale out, says that its values must be serializable, and has the
  error in its symptom tables. The MVC sample and the TestApp run in process; the Web Pages sample uses the provider in
  place of `StateServer`, and the gate checks both.
