## What's new in 0.10.0

### Fixes

- **A request whose path has a `(` keeps its headers** (#170). A path with a `(` that isn't a cookieless-session path
  (`/(S(...))/...`) reached the application without any header IIS has no index for: `Prefer`, `X-Requested-With`,
  `OData-*`, `X-HTTP-Method-Override` and any `X-...` were missing from `Request.Headers`, `ALL_RAW` and Web API's
  `HttpRequestMessage.Headers`. OData keys are in parentheses (`/People(FirstName='Kate',LastName='Jones')`), so a
  `PATCH` with `Prefer: return=representation` answered 204 instead of 200 with the entity (the smoke test's
  `odata-samples-compositekey`). IIS keeps them whatever the path, and CI's `iis-compare` job now checks this against
  IIS 10.
- **A reference to an assembly without a strong name binds whatever the version** (#171), as on .NET Framework, where
  fusion checks versions only for strong-named assemblies. A library built against `Nancy, Version=0.21.1.0,
  PublicKeyToken=null` failed with `FileNotFoundException` when the application deploys Nancy 0.20.0 (JabbR). A
  strong-named reference to a lower deployed version still needs its binding redirect, which isn't applied yet (#158).

### Migration guide

More of what the smoke test's migrations found, in [MIGRATING.md](../MIGRATING.md), [NAMESPACES.md](../NAMESPACES.md)
and [AGENT-MIGRATION.md](../AGENT-MIGRATION.md) (its search list and symptom table):

- **Code:** libraries resolve relative paths against `bin_dotnet/`, so a log written there restarts the application at
  every line (mojoPortal's log4net, #173); `AppDomain.RelativeSearchPath` is null (use `HttpRuntime.BinDirectory`,
  #177); `SecurityProtocolType.Ssl3` throws on .NET (#176); LINQ to SQL's generated SQL, `GetCommand().CommandText` as
  well as `DataContext.Log`, has `\n` on Linux (#175).
- **Views:** a Razor 1 view with `@` before a C# keyword in a code block doesn't parse on Razor 3: wrap it in `@( ... )`
  (#174).
- **Libraries:** any prebuilt .NET Framework library that uses `CallContext` fails with `TypeLoadException`, not only
  Log4Net.Async: SimpleInjector 3.1's ExecutionContextScoping (use 3.3.2, #178).
