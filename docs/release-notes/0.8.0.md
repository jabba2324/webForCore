## What's new in 0.8.0

More of .NET Framework's behaviour where 0.7.0 differed:
- session state uses one cookie (#79);
- files without a BOM are read in the ANSI code page (#90);
- OWIN responses have IIS's headers (#78);
- .NET Framework's `<system.codedom>` entries (#88) and partial trust levels (#87) are accepted.

System.Data.SqlClient is built from Microsoft's source with `GetTypes()` fixed (#41). Pages compile through Roslyn's
public API (#57).
System.Drawing comes from drawingForCore 0.3.0, whose GDI+ engine follows the same code rules.

The repository is reorganised too. Microsoft's code comes from submodules of cleared-down forks (#61), the CI tools are
C#, and the default branch is `main` (#76). CI compares the Web API sample's responses with IIS 10's (#78).

### Upgrading from 0.7.0

Two changes can affect a running application:
- **Session state.** With `UseAspNetCoreSessionProvider()`, sessions stored by 0.7.0 aren't found after the upgrade,
  so users start new sessions (#79).
- **File encoding.** An application whose `.aspx`, `.ascx`, `.master` or `.cshtml` files are UTF-8 without a BOM must
  set `<globalization fileEncoding="utf-8" />`, as on IIS (#90).

Both changes follow .NET Framework, which webForCore matches even where an earlier webForCore did something else.

### Session state: one cookie, as on IIS

`UseAspNetCoreSessionProvider()` keeps each session in ASP.NET Core's `IDistributedCache` (in memory, Redis or SQL
Server), keyed by System.Web's session ID, with `Session.Timeout` as the sliding expiration (#79). There is one session
cookie, `<sessionState cookieName>` (`ASP.NET_SessionId`), with `<sessionState timeout>`, as on IIS. 0.7.0 used ASP.NET
Core's session, which added its own `.AspNetCore.Session` cookie and timeout.

- **Migrating:** remove `AddSession()` and `UseSession()` from `Program.cs`, and register a distributed cache (MIGRATING.md,
  "Session state").
- **Upgrade effect:**
  - Sessions stored by 0.7.0 aren't found, so users start new sessions.
  - An application that set `SessionOptions.IdleTimeout` to control the session's lifetime now gets
    `<sessionState timeout>`.
  - `Session_End` doesn't run, as with any out-of-process session state on IIS.

### Files without a BOM are read in the ANSI code page

Without `<globalization fileEncoding>`, `.aspx`, `.ascx`, `.master`, `.cshtml` and the other files ASP.NET compiles are
read in the ANSI code page when they have no byte order mark, as .NET Framework read them with its `Encoding.Default`
(#90). The code page is:
- on Windows, the system's;
- on Linux, the one Windows has for the locale (`LANG`): windows-1252 for English, Western European and `LANG=C`.

0.7.0 read them as UTF-8, so Windows-1252 characters became `�` (Umbraco 6's installer).

- **Upgrade effect:** UTF-8 files without a BOM now show `’` as `â€™`. Set `<globalization fileEncoding="utf-8" />`, as
  such an application had to on IIS. Files with a BOM are read in its encoding, as before.

### Compatibility fixes

- **OWIN responses:**
  - A response that Katana ends before a handler runs no longer has `X-AspNet-Version` or `Cache-Control: private`,
    as in IIS's integrated pipeline. ASP.NET adds them only around a handler, or when a response is flushed (#78).
  - CI's comparison with IIS 10 finds no other difference in the Web API sample's responses, apart from the server name
    and IIS's own 404 page.
- **`<system.codedom>`** entries naming .NET Framework's `Microsoft.CSharp.CSharpCodeProvider` and
  `Microsoft.VisualBasic.VBCodeProvider`, as .NET 3.5 and 4.0 templates wrote them, compile with System.Web's providers
  and the entries' options (#88). Umbraco 6.2.6's pages failed with an `InvalidCastException`.
- **`<trust level="Medium">`** and the other partial trust levels are accepted and the application runs in full trust
  (#87). 0.7.0 failed every page. .NET has no Code Access Security.
- **Restarts:** a worker no longer deletes App_Code and page assemblies that the running worker still has loaded (#89).
  The next worker's compile had failed with `CS0006`. As on IIS, a page edited while it runs counts towards
  `numRecompilesBeforeAppRestart`.
- **`Assembly.Load("App_GlobalResources")`** returns the compiled App_GlobalResources assembly (#33).
- **A process without a locale** warns when the application starts. This covers `LANG` and `LC_ALL` unset, or `C`,
  `POSIX` or `C.UTF-8`. Requests then run with the invariant culture, which IIS never does, so resources chosen by
  culture name aren't found (#97). Set `<globalization culture>` or the environment's `LANG`.
- **File change monitoring that can't start** (on Linux, when the user has no inotify instances left) shows the
  operating system's reason on the "Configuration Error" page and in the worker's log, at Error level. An `App_Data`
  watcher that failed sent an empty 200 instead of the error page (#115, #107).

### System.Data.SqlClient from Microsoft's source

webForCore builds System.Data.SqlClient 4.9.1 from dotnet/maintenance-packages, in package `webForCore.Data.SqlClient`
(#41). `webForCore.Web` brings it.

- **Fixed:** in Microsoft's builds for .NET 8 and later, `Assembly.GetTypes()` on System.Data.SqlClient throws a
  `ReflectionTypeLoadException`. That broke applications that scan every assembly's types: Opserver, DI containers,
  AutoMapper profiles and MEF.
- **Packages:** the `System.Data.SqlClient` package's assemblies are left out of the build at any version the
  application or its packages reference.
- **Licence:** on Windows, SqlClient uses `sni.dll` from Microsoft's `runtime.native.System.Data.SqlClient.sni` package.
  It is under the Microsoft .NET Library License, which allows redistribution but isn't open source (LICENSING.md).

### Code rules

webForCore's own code gives up the remaining reflection into .NET's internals, P/Invoke and GC steering (#57):
- **Page compilation:** pages compile in process through Roslyn's public API instead of Roslyn's internal `Csc.Run` by
  reflection. The output, assemblies and PDBs are byte for byte csc's and vbc's, and compiles take the same time.
- **Out-of-process compiles:** a command line that needs a csc or vbc process now works in a deployed application.
- **Compilation folder:** its name off Windows ends with the user's name instead of the user's number from `geteuid`.
  For example, `Temporary_ASP.NET_Files-www-data` replaces `Temporary_ASP.NET_Files-33`. The first start after the
  upgrade compiles the application again, and the old folder can be deleted.
- **CI:** `tools/ci/check_code_rules.cs` fails on a new break.

`FrameworkSurrogates` (BinaryFormatter's .NET Framework wire format for `NameValueCollection`) still reads private
fields. It is the one item left on #57.

### Repository

- **Microsoft's code** comes from submodules of xforcore's cleared-down forks, with each of webForCore's changes a
  commit on the fork's `webforcore` branch (#61). The lift tooling and LIFT.md are gone. What was still true moved into
  MODIFICATIONS.md and the other docs.
- **Tests:** races between test classes that share System.Web's static state fixed (#116, #117 open). Each worker uses
  12 to 15 inotify instances, so two IIS gate runs at once can exceed Linux's default of 128 (#107).
- **CI tools** are C# programs (`dotnet run tool.cs`), not Python.
- **The default branch** is `main` (#76). A ruleset requires pull requests and CI.
- **CI:** a new `iis-compare` job serves the Web API sample from IIS 10 on Windows Server 2025 and compares every
  response (#78).
- **Migration guide:**
  - WebActivatorEx runs as it is from 0.7.0, since workers (#21, #56);
  - `bin_dotnet` paths, `Uri`/`VolumeSeparatorChar`, `CS0121`, named wait handles, Log4Net.Async and the invariant
    culture (#91–#97).
