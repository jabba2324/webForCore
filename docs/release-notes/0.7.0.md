## What's new in 0.7.0

webForCore targets **.NET 10 LTS** (#55). Applications run in **worker processes under `webforcore-host`**, as IIS runs
them in application pools, instead of in emulated app domains (#56). System.Drawing comes from its own project,
[drawingForCore](https://github.com/jabba2324/drawingForCore) (#53). The packages are on a NuGet feed. There are also
fixes from the smoke test's fifth round (#49–#52).

### .NET 10 LTS

Every assembly targets `net10.0` instead of .NET 11 RC. .NET 10 is supported until November 2028, which long-lived
ASP.NET 4.x applications need. Microsoft's packages are 10.0.14, and the repository's `global.json` pins SDK 10.0.100
with `latestFeature`. Assembly versions stay 11.0.0.0.

- **Migrating:** retarget the application to `net10.0`.
- **Fixed:** with an SDK newer than the target framework (the .NET 11 SDK building for net10.0), the framework's
  `System.Web` and `System.Web.HttpUtility` facades came from the NuGet cache and weren't removed from the references,
  so builds failed with CS0433/CS7069. They are now removed wherever the targeting pack comes from.

### Worker processes under webforcore-host

Each start of the application runs in its own process, and a restart (a Web.config, bin or App_Code change,
`HttpRuntime.UnloadAppDomain`, a recycling limit) starts a new one. This replaces the in-process app domain emulation,
whose old domains could stay in memory, or crash the process after restarts (#52).

- **`webforcore-host`** (package `webForCore.Host`, which `webForCore` brings) plays the application pool's part.
  It owns the bindings and TLS, starts the application as worker processes, and forwards requests to them over a Unix
  socket. It has IIS's app-pool settings: startup and shutdown time limits, rapid-fail protection, queue timeout, and
  replacing a crashed worker. Run the app with `dotnet bin_dotnet/webforcore-host/webforcore-host.dll`. The
  `WebForCore:Host` configuration section sets the limits (IIS-COMPATIBILITY.md).
- **Restarts don't drop requests:** while a worker shuts down, the host sends new requests to the next one, and
  requests in flight finish within `shutdownTimeout`.
- **The client's connection details** (address, port, scheme, TLS, client certificate) reach the application through
  the host, so `Request.UserHostAddress`, `IsSecureConnection` and `ClientCertificate` are the client's.
- **Removed** (no applications use them yet): `UseWebForms(o => o.IsolateApplication(...))`,
  `RecyclingOptions.MaxStuckDomains`, `AddWebForms(o => o.Systemd = ...)` and the systemd unit. Starting the host at
  boot and restarting it if it stops is the job of your service manager or container.

### System.Drawing comes from drawingForCore

System.Drawing.Common 6.0, its GDI+ engine on SkiaSharp, and Microsoft's tests for it are now drawingForCore's. It's
the same code with the same test results, released as its own packages so that applications outside webForCore can use
it too.

- **Packages:** webForCore no longer produces `webForCore.Drawing` and `webForCore.Drawing.Common`. They are replaced by
  `drawingForCore` (System.Drawing) and `drawingForCore.Common` (System.Drawing.Common), 0.2.0. The `webForCore`
  package depends on them, so an application that references `webForCore` gets them automatically, but its
  `nuget.config` needs drawingForCore's feed. Remove any direct references to the old packages.
- **Fixed:** System.Drawing and System.Drawing.Common both defined `FontConverter`, `ToolboxBitmapAttribute` and
  `BitmapSuffixInSatelliteAssemblyAttribute`, so code that saw both assemblies failed with CS0433. System.Drawing now
  forwards them to System.Drawing.Common.

### The NuGet feed

webForCore's packages are on a feed on GitHub Pages, https://jabba2324.github.io/webForCore/index.json, rebuilt after
each release from the latest five. They are still attached to the GitHub releases, and still not on nuget.org. Add the
feed and drawingForCore's to `nuget.config`:

```xml
<add key="webForCore" value="https://jabba2324.github.io/webForCore/index.json" />
<add key="drawingForCore" value="https://jabba2324.github.io/drawingForCore/index.json" />
```

### Fixes

- **#49:** a change made while the next start was starting no longer leaves the application answering 503 for good.
- **#50:** `AppDomain.CurrentDomain.GetData("DataDirectory")` is the site's `App_Data`, as on IIS. Data providers that
  expand `|DataDirectory|` themselves (System.Data.SQLite) created their databases in `bin_dotnet/`.
- **#51:** changes to `bin` and `App_Code` (and the other critical directories) restart the application on Linux too.
  Only Windows watched them, so a deployment that replaced DLLs kept running the old code.
- **App_Code loaded twice:** typed data controls over App_Code types (a ListView with `ItemType`) failed on the first
  start after a build or a configuration change.

### Tests

23,447 tests in 24 suites on .NET 10 (Linux x64): 23,423 pass, 24 skipped, none fail. The IIS gate suite has 106
tests, and the new Host.Tests checks `webforcore-host` itself. Microsoft's System.Drawing.Common tests run in drawingForCore's
CI (3,882 tests, 151 known failures, mostly metafiles). CI runs every suite on Linux and on Windows, and runs the
package smoke test, with both applications under the host, from the packages.
