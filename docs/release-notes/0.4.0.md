## What's new in 0.4.0

**webForCore now ships only Microsoft assemblies** (CONTRIBUTING.md, principle 1). The two non-Microsoft libraries it
shipped are no longer part of it (#25):

- `webForCore.WebActivatorEx` (in 0.3.0, part of the `webForCore` package);
- `webForCore.AjaxControlToolkit`, `.StaticResources` and `.HtmlEditor.Sanitizer` (0.1.0–0.3.0).

Their 0.1.0–0.3.0 packages stay attached to those releases.

### Behaviour changes when upgrading from 0.3.0

- **WebActivatorEx's start methods don't run on webForCore** (#21). The original package finds its attributes with
  `Assembly.LoadFrom`, which on .NET loads second copies of the application's assemblies outside the application.
  Keep the package and call each `PreApplicationStartMethod` from `Application_Start` in Global.asax, post-start
  methods after it, and shutdown methods from `Application_End` (MIGRATING.md section 3). Without that, a DI container
  that Unity.Mvc, Ninject.MVC or StructureMap.MVC sets up that way is never set up, and controllers fail with "No
  parameterless constructor defined".
- **AjaxControlToolkit isn't provided.** ASP.NET AJAX itself (`ScriptManager`, `UpdatePanel`, page methods), which is
  Microsoft's, is unchanged.
