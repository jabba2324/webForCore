## What's new in 0.6.0

Windows is supported as a development environment (#46, #47), and fixes from the smoke test's fourth round (#44),
found migrating JabbR, Opserver and YAF.NET.

### Windows for development

Linux stays the production target. Most teams with ASP.NET 4.x applications develop on Windows, so webForCore now
builds, runs and passes its tests there too. CI builds, tests, packs and runs the package smoke test on Windows Server
2025 beside Linux, for every pull request and release, and both must pass. The packages are the same on both.

Fixes for applications on Windows:

- **Old app domains are collected after a restart** (a web.config or bin change, `HttpRuntime.UnloadAppDomain`). On
  Windows each restart kept the previous start in memory:
  - **System.Web's telemetry:** .NET Framework's ASP.NET telemetry events cached their types per thread. webForCore no
    longer writes them.
  - **Process-wide waits:** HttpClient's system proxy and network change notifications kept the context of the request
    that started them. The host now starts them first.
  - **SqlClient's connection pools:** a pooled connection's native handle held the domain. The pools are cleared when
    the domain unloads.
- **Default documents** are rewritten to the file's own name, as on Linux: `default.aspx` in the list serves
  `Default.aspx` as `~/Default.aspx`.
- **Protected configuration** uses Windows' own key containers and DPAPI on Windows, as on .NET Framework (unchanged;
  now tested).

### Fixes

- **SignalR and System.Web.DataVisualization have Microsoft's assembly versions** (2.4.3.0 and 4.0.0.0; #40). They
  were 0.0.0.0, so libraries built against Microsoft's (SignalR's SQL Server scale-out, as JabbR has it) failed with
  CS1705.

### Migration guide (MIGRATING.md)

- Every package webForCore depends on is a version floor for the application's reference to it: System.Data.SqlClient
  4.9.1, System.DirectoryServices 11.0 (#42).
- Keep the C# version the code was written for: C# 14's span conversions resolve some calls differently. C# 11's ref
  safety rules apply on .NET 7 and later (#43).

### Known issues

- `Assembly.Load("App_GlobalResources")` and `Assembly.Load("App_Code")` don't work (#33). With
  `<compilation optimizeCompilations="true">`, mojoPortal works.
- `Assembly.GetTypes()` on System.Data.SqlClient 4.9.1 throws on .NET 11 (`SqlGuidCaster`), so applications that scan
  every loaded assembly's types fail unless they catch `ReflectionTypeLoadException` (#41, Opserver).
