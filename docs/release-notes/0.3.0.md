## What's new in 0.3.0

Fixes for the problems the smoke test's second round found by migrating open-source applications with 0.2.0
(ELMAH in SocialGoal, Roadkill, OpenOrderFramework, ApplicantTracking, Bonobo Git Server, ReaLocate, eShopLegacyMVC)
(#24):

- **Microsoft's packages no longer replace webForCore's.** Packages built on MVC, Web API, Katana or WebActivatorEx
  (Unity.Mvc, Autofac.Mvc5, ...) bring Microsoft.AspNet.* back transitively. Microsoft.AspNet.Razor and WebPages could
  win the build's conflict resolution, and MVC views then failed with a `MissingMethodException`. Now each webForCore
  package overrides the Microsoft packages it replaces. The `ExcludeAssets` workarounds in the migration guide are no
  longer needed with the packages (#23).
- **Configuration types reached through `System.dll`** (`SingleTagSectionHandler`, `IConfigurationSectionHandler`)
  are the application's: ELMAH's section handlers work (#19).
- New packages, all in the "Always" set that the `webForCore` package brings:
  - `webForCore.Web.Abstractions` and `webForCore.Web.Routing`: the .NET Framework 4 facades
    `System.Web.Abstractions` and `System.Web.Routing` 4.0.0.0, which MVC 2–4 web.configs and .NET 3.5 libraries
    reference (#20).
  - `webForCore.WebActivatorEx`: WebActivatorEx's start and shutdown methods run. The original package used
    `Assembly.LoadFrom`, which on .NET loads a second copy of the application's assemblies, so they never ran. Its
    `webactivator:assembliesToScan` setting isn't read (#21).
  - `webForCore.Net.Http.WebRequest`: `WebRequestHandler`, which Katana's Google, Facebook, Microsoft Account and
    Twitter providers create. Before, every request failed once one was registered (#18).
- Migration guide: the replaced packages' versions, and Identity 2.0 apps (#17); libraries that don't run on .NET,
  such as Glimpse 1.x and AutoMapper before 12 (#22).

### Behaviour changes when upgrading from 0.2.0

- In builds that use the packages, webForCore's assemblies now win over any version of the Microsoft packages they
  replace (Microsoft.AspNet.Mvc, Razor, WebPages, WebApi, Owin, SignalR, Identity and others), without a warning.
- `Assembly.LoadFrom` still returns a second copy in an application's own code; IIS-COMPATIBILITY.md says what to
  use instead.
