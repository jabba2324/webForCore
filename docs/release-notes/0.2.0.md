## What's new in 0.2.0

Fixes for 15 problems found by migrating real open-source applications (eShopLegacyMVC, eShopLegacyWebForms, Bonobo
Git Server, MiniBlog, Clean Architecture MVC 5, MvcMovie) with 0.1.0 (#16):

- .NET Framework libraries that bind `System.Configuration` 4.0.0.0 now read web.config (#1).
- Two `CacheDependency`s on one file no longer throw on Linux (bundling) (#2).
- `HttpUtility`/`IHtmlString` in application code no longer fail with CS0433 when using the packages (#7).
- `System.Web.DynamicData` is built and part of the `webForCore` package: data controls with `ItemType` work (#8).
  The LINQ to SQL and Entity Framework 1–4 model providers aren't included.
- URL Rewrite: the Wildcard and ExactMatch syntaxes and `{CACHE_URL}` (#10), and a rewrite to `?query` alone (#11).
- `<handlers>` paths that start with `/` match (#12).
- With `RouteExistingFiles`, a route takes a URL that is also a directory, before the trailing-slash redirect (#13).
- Migration guide: packages that need more than a reference (#4, #5, #6, #9, #14), and
  `AppDomain.CurrentDomain.BaseDirectory` documented as the build output (#3).
- New: CONTRIBUTING.md.

### Behaviour changes when upgrading from 0.1.0

- **Rewrite rules webForCore can't read now fail closed.** Requests below their level get 500, and the error is
  logged; at the site root that is every request. 0.1.0 ran without the rules, so a rule that blocked a path stopped
  blocking it (#10).
- **W3C logs moved out of the site** (#15), which served them. The default is `$LOGS_DIRECTORY/W3SVC1` (systemd's
  `LogsDirectory=`; `tools/deploy/webforcore@.service` now sets it), otherwise `logs/<site>/W3SVC1` next to the site
  folder. The process needs write access there. A log folder you put inside the site answers 404.
